# レイアウト・配色の設計規約（Excel 成果物）

「壊れていない」だけでなく **見て分かる・誤入力しにくい・そのまま印刷できる** 状態にするための
配置・配色・書式の既定。`utf_ken_all` / `htmlPCAFmock`（COM ビルドの運用 Excel）で実際に使って
いる規約を、特定業務に依存しない形へ一般化したもの。**既存テンプレに規約があればそちらが優先**。

## 1. セルの役割を色で示す（最重要）

利用者が「どこを触るのか・どこが自動計算か」を一目で区別できるよう、セルの **役割ごとに背景色**を
割り当てる。色は固定値ではなく**意味**で運用する（同じ意味なら全シートで同じ色）。

| 役割 | 背景色 (RGB) | 16進 | 使いどころ |
|------|--------------|------|------------|
| 入力（利用者が手で打つ） | `(255, 255, 204)` | `FFFFCC` 薄い黄 | 申請者・数量・単価など手入力セル |
| マクロ／システム書込（人は触らない） | `(255, 250, 205)` | `FFFACD` 淡い黄 | 起票で採番される番号など。保護でロック |
| 数式・自動計算（読むだけ） | `(242, 242, 242)` | `F2F2F2` 薄い灰 | 合計・比率・XLOOKUP 結果 |
| 無効・入力不要（条件で変わる） | `(220, 220, 220)` | `DCDCDC` 灰 | その行では使わない列（後述の条件付き書式） |

- **入力は黄・計算は灰** を基本軸にする。利用者の視線は「黄を埋めれば完成」で済む。
- 役割が**動的に変わる**セル（仮コード入力時は数式→手入力に変わる等）は、固定塗りではなく
  **条件付き書式**で色を切り替える（[3](#3-条件付き書式で状態を伝える)）。
- 色数は増やしすぎない。意味の数 = 色の数。装飾目的の配色はしない。

### COM / openpyxl での指定

```python
# COM（win32com）— 役割色を定数化してまとめて塗る
COLOR_INPUT   = (255, 255, 204)
COLOR_FORMULA = (242, 242, 242)

def _rgb(r, g, b):           # Excel は BGR の整数
    return r | (g << 8) | (b << 16)

def set_fill(rng, rgb):
    rng.Interior.Pattern = 1                 # xlSolid
    rng.Interior.Color = _rgb(*rgb)

set_fill(ws.Range("B2:B3"), COLOR_INPUT)     # 入力帯
set_fill(ws.Range("B28"), COLOR_FORMULA)     # 合計（数式）
```

```python
# openpyxl（ヘッドレス代替）
from openpyxl.styles import PatternFill
INPUT = PatternFill("solid", fgColor="FFFFCC")
ws["B2"].fill = INPUT
```

## 2. 配置（レイアウト）の型

- **入力 → 集計 → 判定 → メタ** の順に上から下／左から右へ流す。利用者が記入する順に並べる。
- **ラベル列と値列を分ける**（例: A 列ラベル・B 列値）。1 セルにラベルと値を混在させない。
- **空行・空列を区切りに使う**。論理ブロックの境目に 1 行（1 列）の余白を入れると、罫線を増やさず
  に視覚的にまとまる（例: 申請者ブロックと明細の間に空行）。
- **見出しは太字**。シートタイトルは太字 14pt 程度、表ヘッダは太字＋薄い塗り。
- **内部データは別シートに隔離**して very hidden にする（[5](#5-内部データの隔離と表示制御)）。
  表に出す表示用シートと、参照される素データ・正解値（パスコード等）の SoT を分ける。

## 3. 条件付き書式で状態を伝える

「この行ではこの列は不要」を**塗りで**伝える。値で出し分けせず、書式で無効化する。

- 例: 「価格改定」以外の行は「現単価」列をグレーアウト（無効色）。
- 例: 標準原価が登録済みの品目は「仕入原価」列をグレーアウト（手入力不要）。
- 例: 仮コード（`仮-` 接頭辞）行は、通常は数式色の名称セルを**入力色**に切り替えて直接入力を促す。

固定塗りでなく条件付き書式にするのは、**データが変わると役割も変わる**セルを正しく追従させるため。

## 4. 数値・日付・文字の書式

| 種別 | 書式 | 備考 |
|------|------|------|
| 金額・件数 | `#,##0` | 桁区切り。単位は見出しに（「売上（千円）」） |
| 通貨 | `¥#,##0` / `$#,##0` | 記号は混在させない |
| パーセント | `0.0%` | 既定は小数 1 桁 |
| 日付 | `yyyy/mm/dd` | 文字列日付を避け、シリアル値＋表示書式 |
| 年（西暦） | 文字列扱い `@` | `2,024` のような桁区切りを付けない |
| 倍率 | `0.0x` | バリュエーション等 |

- 列ごとに `NumberFormat` を範囲一括で設定する（セル単位ループを避ける）。
- 長い文字列（品目名など）は **折り返しでなく「縮小して全体を表示」（ShrinkToFit）** を優先し、
  行高を一定に保つ。意図的に複数行見せたいメモ欄だけ `WrapText=True` ＋行高拡張にする。
- フォントは 1 ブック内で混在させない（既定: Yu Gothic UI 等の和文 UI フォント）。

## 5. 内部データの隔離と表示制御

- 参照専用の素データ・検索元・正解値（パスコード等）・ルーティング数式は **very hidden**
  （COM: `ws.Visible = 2` / `xlSheetVeryHidden`）にして、利用者の目と編集から隔離する。
- 表示するワークシートには「表示する情報」だけを置く。表示用と SoT 用を1枚に混ぜない。
- 管理者向けに一括「全表示／元に戻す」を用意する場合は、表示状態をスナップショットして復元できる
  ようにし、ゲート（合言葉入力など）を付ける。

## 6. 印刷で完結させる（印刷規律）

配布物・帳票は「印刷してそのまま回せる」ことを前提にする。

- **印刷範囲を明示**する（`PageSetup.PrintArea = "A1:L24"`）。集計・メタ・内部欄は**印刷範囲外**に置く。
- **1 枚に収める**: `Zoom=False` ＋ `FitToPagesWide=1` / `FitToPagesTall=1`。倍率ベタ指定はしない。
- 向き・余白を固定する（例: 横向き `xlLandscape`、左右余白 0.25in 程度の狭余白）。
- シート上にフォームボタンを置かない方針なら、操作はリボン／メニューに寄せ、印刷面を汚さない。

```python
ps = ws.PageSetup
ps.PrintArea = "A1:L24"
ps.Orientation = 2          # xlLandscape
ps.Zoom = False
ps.FitToPagesWide = 1
ps.FitToPagesTall = 1
ps.LeftMargin = app.InchesToPoints(0.25)
ps.RightMargin = app.InchesToPoints(0.25)
```

## 7. 列幅・行高

- **内容量に応じて列幅を変える**。コード列は基準幅、名称・摘要は 2〜3 倍。一律幅にしない。
- 行高は原則一定。折り返しメモ欄など必要箇所だけ広げる。
- 幅・高さ・座標などのレイアウト定数は**ビルドスクリプト（と VBA）の定数に集約**し、マジック
  ナンバーを散らさない（座標を変えるときは1か所で）。

## チェックリスト（レイアウト・配色）

- [ ] 入力＝黄・計算＝灰など、**役割が色で区別**できる（意味の数＝色の数）。
- [ ] 動的に役割が変わるセルは**条件付き書式**で色を切り替えている。
- [ ] 論理ブロックは**空行・空列**で区切り、罫線を増やしすぎていない。
- [ ] 金額 `#,##0`・日付 `yyyy/mm/dd`・率 `0.0%` など**書式を範囲一括**で設定した。
- [ ] 長文は **ShrinkToFit** で行高を保ち、フォントを混在させていない。
- [ ] 素データ・正解値・ルーティングは **very hidden** に隔離した。
- [ ] **印刷範囲を明示**し、集計・メタは印刷範囲外、1 枚に収まる設定にした。
- [ ] レイアウト定数を**ビルド側に集約**し、座標を直書きで散らしていない。
