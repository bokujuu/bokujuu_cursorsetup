# Web Research Resolve

課題を Web 検索で調べ、解決策を評価・設計・実装・検証する手順。旧 `.cursor/commands/websearch-resolve.md` を skill 化したもの。

実装フェーズでは `implement-with-practices` と併用するとよい。

## 1. 課題の明確化

- [ ] 課題を 1〜3 文で要約
- [ ] 期待する成果物・制約・対象バージョンを整理
- [ ] 関連ファイルを列挙

## 2. Web 検索

- [ ] 主要キーワードと同義語を列挙
- [ ] 3〜5 個のクエリで検索（直近 1〜2 年・バージョン一致を優先）

### クエリテンプレート

- `{課題} {言語/フレームワーク} {バージョン}`
- `{エラーメッセージ} fix OR workaround {バージョン}`
- `{API名} best practices {year}`
- `{ライブラリ} migration {from} to {to}`

## 3. 情報の評価

- [ ] 一次情報（公式 docs、リリースノート、RFC）を優先
- [ ] 信頼性・再現性・環境適合性で採点
- [ ] 有力候補を 3 つに絞り比較

## 4. 設計

- [ ] トレードオフ（工数・影響・性能・セキュリティ）
- [ ] 採用案・代替案・却下理由
- [ ] 導入・ロールバック手順

## 5. 実装

- [ ] ブランチ作成（例: `feature/research-{短い課題名}`）
- [ ] 小さなコミットに分割
- [ ] Lint / 型 / テスト / ビルド
- [ ] 受け入れ基準で動作確認

## 6. 記録

- [ ] 参照 URL と要点を `RESEARCH.md` または PR 説明に記録
- [ ] 決定理由を `DECISIONS.md` または ADR に記録
- [ ] フォローアップを Issue 化

## RESEARCH.md テンプレート

```markdown
## {課題名} - 調査ログ
### 目的
{一言}

### 探したこと
- クエリ: "{クエリ1}", "{クエリ2}"
- ノート: {気づき}

### 参考
1. [タイトル]({URL}) - {要点}

### 方針
- 採用案: {概要}
- 代替案: {概要}
- ロールバック: {手順}
```

## 補助コマンド

- 変更箇所: `rg "{キーワード}" -n`
- 影響範囲: `git grep -n "{識別子}"`
- セッション引き継ぎ: `cursor-session-doc` skill
