# notes（コメント）方針

Power Query M のコメントは、**後から読む人が「何のためか」を短時間で復元できる**ことを目的にする。装飾や網羅のためのコメントは書かない。

## 方針

1. **既存コメントは保持** — 十分な箇所は無視する。矛盾や誤りがあるときだけ直す。
2. **プロジェクト規約を優先** — 既存の言語・体裁・必須ヘッダー形式があればそれに従う。規約がなければ日本語を優先する。
3. **高レベルを優先** — ステップの目的と概要。実装の逐語解説は複雑な箇所だけ。
4. **理由を残す** — フィルタ条件、マージ種別、置換・分岐、Buffer 導入の意図が分かるようにする。

## 入れる場所（優先順）

1. クエリ先頭（名前と目的の 1〜2 行）
2. 意味の区切りになるセクション（読み込み／整形／結合／集計／出力）
3. 複雑な計算・多条件フィルタ・マージ・参照表マージ・Buffer / StopFolding 導入箇所

## ヘッダー例（規約が無いとき）

```m
// ============================================================================
// Query: [クエリ名]
// 目的: [1〜2行]
// ============================================================================
```

## ステップコメントの要点

- 1 行で目的が足りるならそれでよい。計算が非自明なときだけ追記する。
- フィルタは「何を残す／落とすか」と理由。
- マージは相手・結合種類・目的。未一致時の扱いが重要なら一言残す。
- Buffer / StopFolding は「なぜここで必要か」を残し、配置見直し後の手段であることを示す。

## やらないこと

- 自明な代入へのコメント連打
- 言語の二重化（既存が英語なら英語に揃える、など）
- ロジック変更をコメントだけで隠蔽する（変更するなら報告と検証を伴う）
