# ボリューム階層（Volume Tiers）

「行数が少ない」「増やしたら使い勝手が悪い」の両方は、**tier を混同している**ことが多い。
用途ごとにファイル（またはシート）を分け、件数とカバレッジの目的を一致させる。

## Tier 一覧

| Tier | 件数目安 | 実行時間目安 | 主目的 |
|------|----------|--------------|--------|
| `smoke` | 各境界 1 + アンカー 3〜10 | 秒 | CI スキーマ・参照の最短経路 |
| `dev` | 50〜500（ドメイン依存） | 秒〜十秒 | 日常開発・手動デモ・集計の見た目 |
| `stress` | 1k〜要件上限 | 分 | 性能・Excel 再計算・UI 仮想スクロール |
| `negative` | 5〜30 | 秒 | エラー表示・バリデーション・ロールバック |

**ルール**

- 1 ファイルに全 tier を詰め込まない（特に `negative` は分離）。
- tier を上げるときは **カバレッジ行列を先に増やさない** — グループ配分とアンカーを smoke で固めてから dev で倍増する。
- ユーザーが「もっと欲しい」と言ったら、まず **どの tier か** を確認する。

## ドメイン別の dev tier 目安

| ドメイン | dev 目安 | 理由 |
|----------|----------|------|
| マスタ 1 テーブル | 30〜100 | フィルタ UI で「複数ページ」が見える程度 |
| トランザクション + 明細 | 親 50 × 子 3〜5 | 集計・JOIN の偏り検出 |
| 運用 Excel（PCAF 型） | シートごとに 20〜200 | ピボット・条件付き書式・印刷範囲 |
| 取込 CSV（バッチ） | 100〜1000 行 | エラー行が全体の数%でも絶対件数が要る |

## smoke の組み立て方

smoke は「小さいランダム」ではない。**カバレッジ行列の各カテゴリから最低 1 行**を選ぶ。

```text
行 = アンカー（正常） + 各境界カテゴリ 1 行 + グループ代表（状態ごと 1）
```

件数は増えてもよいが、**検証時間が dev を超えない**こと。

## dev の組み立て方

1. smoke の行をそのまま含める（ID 不変）。
2. 残りをグループ比率に従い追加生成。
3. 追加行だけ `row_seed` を変える — smoke 行は書き換えない。

これにより「行数を増やしたらアンカーが変わってテストが壊れる」を防ぐ。

## stress の注意

- 生成と verify を分離し、stress 専用コマンドにする（日常 CI では回さない）。
- Excel の場合は `excel-deliverable-quality` の全件エラー走査がボトルネックになりうる — tier ごとに verify 範囲を切る。

## negative tier

- ファイル名に `negative` または `_invalid` を含める。
- 正データの ID 空間と **意図的に重複させない**（誤投入防止）。
- 1 ファイル 1 種類の壊し方に寄せる（「全部壊れ」はデバッグしづらい）。
