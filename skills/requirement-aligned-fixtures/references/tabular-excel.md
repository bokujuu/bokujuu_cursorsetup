# 表形式・運用 Excel（PCAF 型）向け

`htmlPCAFmock` / `utf_ken_all` 等で顕在化した不満の多くは、**表としての設計ミス**が
Excel ビルド・数式エラーとして表面化する。帳票規約は `excel-deliverable-quality`、
**素データの設計**は本節を参照する。

## 典型の不満と原因

| 不満 | よくある原因 | 本 skill での対処 |
|------|--------------|-----------------|
| 行数が少なく実用性がない | smoke だけ作っている | `dev` tier とグループ配分を spec 化 |
| 増やすとバランスが悪い | 一様乱数で状態・部署が偏る | 三軸バランス・グループ先固定 |
| 数式・参照が壊れる | マスタキーが不安定・欠損 | アンカー ID・FK 検証 |
| エラー境界のテストができない | 正常データだけ | `negative` tier を分離 |
| 手修正で再現不能 | xlsm 直編集 | スクリプト生成 + manifest |

## シート・ファイル構成

| 種別 | 推奨 | 備考 |
|------|------|------|
| 入力用素データ | スクリプトが CSV または hidden シートへ | COM ビルドで注入 |
| 正解値・ルーティング | very hidden 相当（プロジェクト規約に従う） | 利用者画面と分離 |
| デモ用表示データ | `dev` tier | 印刷・ピボット確認用 |
| 壊れた取込例 | `negative` 別ファイル | 正データと混在しない |

`excel-deliverable-quality` の「内部データ very hidden 隔離」と矛盾しないよう、
**どのシートが SoT か**を spec に書く。

## クロスシート・クロスファイル参照

1. **マスタを先に生成** — トランザクションより先に smoke アンカーを固定。
2. **参照キーは文字列で統一** — 数値と文字列の暗黙変換を避ける（先頭ゼロ・日付シリアル）。
3. **名前定義・構造化参照が絡む場合** — 行追加で範囲がずれないよう、テーブル行数は spec の `row_count` と一致させる。
4. **削除済み行** — フィルタ非表示ではなく、データ上は「論理削除」フラグ行として残すかどうかを仕様に合わせる。

## 状態機械（承認・ワークフロー）

グループ軸 `status` は **件数配分を spec に固定**する。

```text
下書き → 申請 → (差戻し ↔ 再申請) → 承認
```

- 各遷移に必要な列（申請日・承認者・コメント）を状態ごとにテンプレ化。
- 「差戻し」は全体の 10% など、**稀だがゼロでない**件数を dev で確保。
- 同一申請の再申請は **同じ business_key・別 revision** など、追跡規則を spec に書く。

## 日付・金額・率

- 日付は `frozen_clock` 基準の相対日（+0, +1, -30 日）で揃える。
- 金額はグループごとに範囲を変えてもよいが、**集計の見える化**（部署別合計が桁違いにならない）を spot check。
- 率・割合は分子分母を別列に持ち、丸めを Excel 側に任せる場合は生成値を過剰精度にしない。

## 取込 CSV（utf_ken_all 型）

- 文字コード・BOM・改行を spec に固定。
- 郵便番号・電話・コード類は **常に str**（pandas `dtype=str` 想定）。
- バッチ単位で `batch_id` を付け、エラー行だけ negative ファイルに分離。

## 検証の接続

1. fixture verify（件数・FK・タグ）— 本 skill の完了条件
2. COM / openpyxl verify（数式エラー 0）— `excel-deliverable-quality`

両方のコマンドを manifest に列挙する。

## プロジェクトローカル skill 化

PCAF 固有の列名・状態名・プールは **global に入れない**。`implement-with-practices` で
`.codex/skills/pcaf-fixtures/` 等に落とし、本 skill は手順と三軸・tier の枠のみを提供する。
