# 三軸バランス — 決定性・変動・グループ性

ダミーデータで最も多い失敗は、**三軸を同時に満たそうとせず、乱数だけ増やす**ことである。
設計は常に **グループ → アンカー → グループ内変動 → 決定性の固定** の順で行う。

## 1. グループ性（Grouping）— 最初に決める

検証目的から「まとまり」を定義する。例:

| ドメイン例 | グループ軸 | なぜ必要か |
|------------|------------|------------|
| 承認ワークフロー | 状態（下書き/申請中/承認/差戻し） | フィルタ・集計・画面遷移 |
| 組織マスタ | 部署・拠点 | 権限・ロールアウト |
| 時系列取引 | 月次バケット | ピボット・締め処理 |
| 取込 CSV | ファイル単位・バッチ ID | エラー行の局所化 |

### グループ配分の決め方

1. **均等配分はデフォルトにしない** — 本番に近い偏り（例: 承認済 70%）が要件なら明示する。
2. **最小グループサイズ** — 集計・パーセンタイルを見るならグループあたり最低 5 件（dev tier）。
3. **クロス集計** — 2 軸以上あるときは「セルあたり 1 件だけ」にならないよう、行列の空セルを先に洗い出す。

### アンカー行（固定行）

次は **seed に依存せず毎回同一** の行として先に置く:

- 各境界カテゴリの代表 1 行（coverage-matrix の必須項目）
- ドキュメント・スクリーンショット用の「説明しやすい」行
- 他テーブル・他シートから参照されるマスタキー

アンカー行には安定した `id`（または業務キー）を付け、生成ロジックのコメントで `ANCHOR:` とマークする。

## 2. 変動（Variation）— グループ内だけ

グループが決まったあと、**グループ内**でだけ変動させる。

| 手法 | 向く場面 | 注意 |
|------|----------|------|
| 有限プールからの抽選 | 名前・住所・商品名 | プールサイズ < 行数なら重複は意図的か確認 |
| パラメトリック（min/max 内一様） | 金額・数量 | 端だけ別アンカーで足す |
| 相関付き生成 | 単価×数量=金額 | 不変条件を生成時に検証 |
| シーケンス + オフセット | 連番 ID | 並列 worker では worker オフセットを足す |

**アンチパターン**

- 全行独立乱数 → グループ比率が二項分布でブレ、dev tier では「たまたま空の状態」が出る
- LLM に丸投げ → スキーマは通るがビジネス不整合（合計不一致・未来日付）が紛れ込む

## 3. 決定性（Repeatability）— 最後に固定

再現性のため、次を **単一の canonical seed** から派生させる:

```text
master_seed = 環境変数 FIXTURE_SEED または spec に記載の整数
group_seed  = hash(master_seed, group_id)
row_seed    = hash(group_seed, row_index)
```

固定するもの:

- `random` / `numpy` / Faker 等の seed（ライブラリごとに明示）
- **基準日時**（`freeze_time` 相当。日付境界テスト以外は固定）
- **出力ソートキー**（暗黙の DB 順に依存しない）
- CSV の delimiter・quoting・改行コード

変えてよいもの（意図的に）:

- `negative` tier 専用ファイル（別 seed でもよいが manifest に記載）
- 探索的カオステスト（自動回帰ゲートには入れない）

## 4. 三軸の合成例（dev tier・承認 100 行）

| 要素 | 設計 |
|------|------|
| グループ | 下書き 10 / 申請中 20 / 差戻し 10 / 承認 60 |
| アンカー | 各状態 1 行 + 境界（空コメント・最大長タイトル）各 1 行 |
| 変動 | 各グループ内で申請者・金額・日付を `row_seed` で生成 |
| 決定性 | `FIXTURE_SEED=42`、基準日 `2026-06-01`、出力は `id` 昇順 |

## 5. チェックリスト

- [ ] グループ比率が spec と一致（±0 件、丸め誤差を許さないなら厳密一致）
- [ ] アンカー行の ID が他ファイル・シートの参照と一致
- [ ] 同一 seed で 2 回生成し checksum が一致
- [ ] 変動フィールドに「意味のない重複」がないか spot check
