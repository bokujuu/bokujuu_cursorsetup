# Codex MCP利用戦略

## 目的
- Codex MCP をコーディング・設計の**レビュワー**として使うルール。**編集は許可しない**（チャット返答のみ）。

## いつ使うか
- **標準タスク（🟡）以上**: 実装後・コミット前に Codex レビューを検討。
- **重要タスク（🔴）**: 設計/API/セキュリティ/本番影響は、方針段階と実装後の両方で依頼。
- **対象外**: 自動生成物・バイナリ・依存の実装詳細・UI文言のみ・手を入れない既存コード。

## コンテキストの渡し方（cwd でコンテキストを与える）

- **cwd**: 必ず渡す。レビュー対象の**絶対パス**（ワークスペースルート、または対象ファイルの親ディレクトリ）。Codex は cwd を**作業範囲**とし、その中でファイル読取・一覧ができる。ファイル内容の自動投入ではないので、必要情報は **prompt でも渡す**。
- **prompt**: 目的・対象（ファイル/箇所）・評価観点を明示。要約や重要箇所も書く。説明だけの依頼はしない。
- 大規模なとき: 優先ファイルに絞るか、観点ごとに分割（目安 5–10 ファイル）。

## 呼び出し引数

- **cwd**: 絶対パス（必須）。
- **prompt**: 依頼文（必須）。
- **sandbox**: `"read-only"` のみ。ファイル書込禁止。シェル実行も行わない（読み取り系コマンドも依頼しない）。
- **approval-policy**: `"never"`。失敗時は未検証範囲・残余リスクを返すよう依頼する。

## プロンプトの最小セット
- 目的（コード/設計レビュー・観点の確認）
- 対象（ファイル・変更概要）
- 評価観点（正確性・安全性・性能・保守性のうち依頼するもの）
- 除外範囲（あれば簡潔に）

## レビュー出力の依頼
- 指摘時: 重大度（Critical/High/Medium/Low）・該当箇所（path:line）・指摘内容・根拠・確信度（High/Med/Low）・推奨修正・未確認事項。
- 指摘なし時: 残留リスク・未検証項目を必ず記載するよう依頼する。

## その他
- **並列**: 複数観点は並列呼び出し可（各回 cwd・sandbox read-only）。
- **フォールバック**: 未接続・タイムアウト時は再試行最大2回→手動レビュー。結果をユーザーに報告。
- **機密**: コードに機微・認証情報を含めない。含む場合はマスキングまたは送信範囲を限定。

## 禁止
- cwd を渡さず説明だけで依頼しない。
- sandbox は常に `read-only`。編集依頼は行わない。
