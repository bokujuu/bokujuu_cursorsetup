# 目的と適用範囲
- CursorやAI向けのルールファイル（`.mdc`）を作成・更新する際の標準的なガイドラインを定義
- コンテキスト消費を最小化しつつ、必要な動作を確実に含めることを目的とする

# 基本原則

## 簡潔性の原則
- **冗長な説明を避ける**: 背景説明は最小限に。必要な情報のみを記載
- **重複を排除**: 既存ルールとの重複を避け、参照で代替可能な場合は参照を優先
- **箇条書きを活用**: 長文の説明より箇条書きで要点を明確化

## 動作の明示
- **すべき動作を具体的に記述**: 「〜すべき」「〜推奨」などの曖昧な表現を避け、具体的な動作を明記
- **禁止事項を明確化**: 「〜してはいけない」を具体的に列挙
- **条件を明示**: 「〜の場合」などの条件分岐を明確に記述

## 構造化
- **見出しで階層化**: 最大3階層まで（`#` → `##` → `###`）
- **箇条書きで整理**: 関連事項は箇条書きでまとめる
- **優先順位を反映**: 最重要事項を先頭に配置

## 例示の指針
- **必要最小限の実例**: 長いコード例は避け、要点を示す短い例のみ
- **実例は簡潔に**: 10行を超えるコード例は避ける（必要なら別ファイル参照）
- **コメントで意図を明確化**: コード例には簡潔なコメントを付与

# ルールファイルの構造

## YAMLフロントマター（必須）
```yaml
---
name: ルール名
version: 1.0.0
description: 1行で簡潔に説明
appliesTo: always | python | javascript | ...
---
```

## 本文の構成
1. **目的と適用範囲**: 1-2行で簡潔に
2. **基本原則**: 最重要事項を先頭に
3. **具体的なガイドライン**: 箇条書きで整理
4. **実例**: 必要最小限のみ
5. **参照**: 関連ルールファイルへの参照

# チェックリスト
- [ ] 冗長な説明を削除し、必須情報のみを記載
- [ ] すべき動作を具体的に記述（曖昧な表現を排除）
- [ ] 見出し階層は最大3階層まで
- [ ] コード例は10行以内
- [ ] 既存ルールとの重複を確認し、参照で代替可能か検討
- [ ] 最重要事項を先頭に配置
