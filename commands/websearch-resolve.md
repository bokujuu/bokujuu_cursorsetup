# Web検索で課題を調査して実装する

## 概要
現在の課題に対して Web 検索で情報を収集し、解決策を評価・設計・実装・検証するための手順。

## ステップ
1. **課題の明確化**
   - [ ] 課題を1〜3文で要約
   - [ ] 期待する成果物/挙動、制約、対象バージョンを整理
   - [ ] 関連ファイル/箇所を列挙

2. **Web検索の実行**
   - [ ] 主要キーワードと同義語を列挙
   - [ ] 下記テンプレートで3〜5個のクエリを作成し検索
   - [ ] 直近1〜2年の情報を優先（バージョン一致を確認）

3. **情報の収集と評価**
   - [ ] 一次情報（公式ドキュメント、リリースノート、標準仕様）を優先
   - [ ] 信頼性（出典・日付・著者）、再現性（コード・手順）、適合性（環境/バージョン）で採点
   - [ ] 有力な候補を3つに絞り比較

4. **解決策の設計**
   - [ ] 候補のトレードオフを比較（工数、影響範囲、性能/セキュリティ）
   - [ ] 採用案・代替案・却下理由を明記
   - [ ] 導入手順とロールバック手順を設計

5. **実装**
   - [ ] ブランチ作成（例: `feature/research-{短い課題名}`）
   - [ ] 変更を小さなコミットに分割（実装とリファクタリングを分離）
   - [ ] Lint / 型 / テスト / ビルドを通す
   - [ ] 実装後の動作確認（受け入れ基準で検証）

6. **記録と共有**
   - [ ] 参照URLと要点を `RESEARCH.md`（または PR 説明）に記録
   - [ ] 決定理由と却下案を `DECISIONS.md`（または ADR）に記録
   - [ ] フォローアップ（ドキュメント整備、技術負債）を Issue 化

## 検索クエリテンプレート
- "{課題のキーワード} {言語/フレームワーク} {バージョン}"
- "{エラーメッセージ} fix OR workaround {バージョン}"
- "{機能/API名} best practices {year}"
- "{ライブラリ名} migration {from_version} to {to_version}"
- "{組み合わせ} performance OR security"

## 評価チェックリスト
- [ ] 公式ソースに基づく（docs, RFC, release notes）
- [ ] 記事が最新/更新日が明記されている
- [ ] バージョン/環境が一致
- [ ] コード/再現手順が具体的
- [ ] ライセンスや利用許諾に問題がない

## 実装チェックリスト
- [ ] 失敗するテストの追加 or 既存テストの拡充
- [ ] 例外・エッジケース・ログのカバレッジ確保
- [ ] ドキュメント・注釈の更新
- [ ] 計測（性能/監視/トレース）とリグレッション防止

## テンプレート
- `RESEARCH.md` 追記テンプレート:
```
## {課題名} - 調査ログ
### 目的
{一言で}

### 探したこと
- クエリ:
  - "{クエリ1}"
  - "{クエリ2}"
- ノート:
  - {気づきや注意点}

### 参考
1. [タイトル]({URL}) - 要点: {1-2行}
2. [タイトル]({URL}) - 要点: {1-2行}

### 方針
- 採用案: {概要}
- 代替案: {概要}
- ロールバック: {手順}
```

- PR 説明テンプレート:
```
目的: {なぜ}
変更概要: {何を}
検証: {どうやって}
影響範囲: {どこに}
フォローアップ: {次にやること}
```

## 任意（自動化ヒント）
- 変更箇所の発見: `rg "{キーワード}" -n`
- 影響範囲の確認: `git grep -n "{識別子}" | cut -d: -f1 | sort -u`
- 差分スナップショット: `commands/step-snapshot.md` を参照
