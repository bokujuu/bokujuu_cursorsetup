# モード: migration（移行・既存データ）

## 目的

旧システム・旧形式のデータを新システムに投入したときの不整合・欠損・回帰を検出する観点を固定する。

## 入力（最低限）

- 移行仕様（マッピング表・対象テーブル/ファイル）
- サンプル旧データ（匿名化済み）または生成ルール
- 移行後の正とするデータモデル

## 観点の追加ルール

- **P5 を最優先**: 件数・チェックサム・NULL 率・参照整合・文字コード
- P4: 移行バッチのログと実 DB の突合
- P6: 移行対象外機能が壊れていないか（移行は範囲外の回帰を起こしやすい）
- P7: 移行仕様と実装スクリプトの差分

## ケース化の正

移行モードでは「画面操作」より **データ不変条件** を正とする。

| 不変条件の例 | ペルソナ |
|--------------|----------|
| 行数一致 | P5 |
| 主キー重複なし | P5 |
| 外部キー孤児なし | P5 |
| 移行前後の集計値一致 | P4, P5 |

## 出力例（観点のみ・抜粋）

```text
P5 [移行担当]: 旧 CSV の文字コード Shift_JIS 行が UTF-8 化後も文字化けしないか
  根拠: 移行仕様 3.1 エンコーディング
P5 [移行担当]: 子テーブル件数が親の削除済み行と矛盾しないか
  根拠: 移行マッピング表 FK-07
```
